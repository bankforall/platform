# Decision Record — กติกาที่เคยค้าง (2026-10-04)

[← v2](./README.md)

เอกสารนี้ปิดคำถามที่ค้างใน [rules-spec.md §7](./rules-spec.md#7-คำถามที่ยังเปิดอยู่) และ [security.md §3](./security.md#3-ความเสี่ยงที่ยอมรับและยังต้องทำ)
ข้อจำกัดที่ทุกการตัดสินใจต้องเคารพ: **ระบบไม่ถือเงิน** (ไม่มี escrow/กองทุนกลาง) ดังนั้นการชดเชยต้องมาจาก "การหักกลบ" ระหว่างสมาชิกเท่านั้น
ตัวเลขทุกตัวเป็นค่าที่ admin ปรับได้ใน `CircleFactory` (ต้องยืนยันกับนักกฎหมายก่อน mainnet)

## D1. ชดเชยผู้รับเงินเมื่อมีคนผิดนัด → **หักกลบหนี้ (set-off) อัตโนมัติ**

เมื่อ D ผิดนัดไม่จ่ายให้ R สัญญาบันทึก `owed[D][R] += ยอดที่ค้าง` เมื่อถึงรอบที่ **D เป็นผู้รับ** ยอดที่ R ต้องจ่ายให้ D จะถูกหักด้วยหนี้ที่ D ค้าง R
(ตามหลักหักกลบลบหนี้ ป.พ.พ. ม.341) ถ้าหักแล้วเหลือ 0 การชำระนั้นถือว่าเสร็จทันทีโดยไม่ต้องโอน

| กรณี | ผล |
| --- | --- |
| D ผิดนัด **ก่อน** ถึงรอบที่ตัวเองได้รับ | ผู้เสียหายทุกคนได้ชดเชยเต็มจำนวนในรอบของ D (D ได้รับน้อยลงตามหนี้) |
| หนี้มากกว่ายอดที่ต้องจ่าย D (เช่น Float ที่ D ค้างทั้งต้น+ดอก) | หักได้เท่ายอดที่ต้องจ่าย ส่วนเกินยังเป็นหนี้คงค้าง (บันทึกเป็นหลักฐาน) |
| D ผิดนัดกับหลายคน | หักกลบรายคู่ แต่ละคนได้คืนจากส่วนที่ตัวเองต้องจ่าย D |
| D จ่ายย้อนหลัง (ผู้รับกดยืนยันการจ่ายล่าช้า) | หนี้ลดลงตามยอดที่จ่าย ไม่ถูกหักซ้ำ |
| หนี้ถูกหักกลบไปแล้วแต่ผู้รับเผลอยืนยันการจ่ายล่าช้าอีก | หนี้ไม่ติดลบ (ใช้ค่าต่ำสุด) — ความผิดพลาดนี้อยู่ฝั่งผู้รับ และเห็นได้ในรายงานหลักฐาน |
| D ผิดนัด **หลัง** ได้รับเงินแล้ว ("ดึงแล้วเชิด") | หักกลบไม่ได้ (D ไม่มีรอบรับอีก) → ใช้มาตรการ D2, D5 และหลักฐานดำเนินคดี — **ระบบที่ไม่ถือเงินชดเชยกรณีนี้ไม่ได้ จึงต้องป้องกันด้วย D2** |
| D เปลี่ยนกุญแจ (rotation) | หนี้ย้ายไปกุญแจใหม่ทั้งฝั่งลูกหนี้และเจ้าหนี้ |
| จ่ายบางส่วน | ไม่รองรับบนระบบ: ผู้รับเลือกยืนยัน (ถือว่ารับครบ) หรือปฏิเสธ แล้วใช้ dispute บันทึกข้อตกลง |

## D2. กันความเสี่ยง "ดึงแล้วเชิด" → **สมาชิกใหม่รับเงินช่วงครึ่งแรกไม่ได้ ถ้ามีสมาชิกที่น่าเชื่อถือ**

"น่าเชื่อถือ" = คะแนน ≥ `trustedReputation` (ค่าเริ่ม **110**; ผู้ผ่าน KYC เริ่มที่ 100 และได้ +2 ต่อการจ่ายตรงเวลา จึงต้องมีประวัติจ่ายดีอย่างน้อย 5 งวด
หรือผู้ตรวจ KYC ให้คะแนนเริ่มต้นสูงขึ้นสำหรับคนที่ยืนยันรายได้/ชุมชนได้)

| รูปแบบวง | กติกา (รอบที่ 1 ถึง ⌊N/2⌋) |
| --- | --- |
| Float / Discount | ผู้ชนะ = ผู้เสนอสูงสุดในกลุ่มที่น่าเชื่อถือ; ถ้ากลุ่มนี้ไม่มีใครเสนอ → สมาชิกที่น่าเชื่อถือคนแรกตามลำดับ (ดอก 0); ถ้าไม่มีสมาชิกที่น่าเชื่อถือเหลือเลย → ใช้กติกาปกติ (กันวงค้าง) |
| Fix | ที่นั่งครึ่งแรกจองได้เฉพาะผู้ที่น่าเชื่อถือ — วงที่ไม่มีผู้น่าเชื่อถือพอจะเต็มไม่ได้และหมดอายุตาม D4 |
| มือนายวง (`hostTakesFirst`) | ใช้ได้เฉพาะนายวงที่น่าเชื่อถือ (กัน "ท้าวแชร์เชิด" ซึ่งเป็นการโกงที่พบบ่อยที่สุด) |
| รอบหลังครึ่ง | ไม่มีข้อจำกัด |
| N = 2 | รอบ 1 ต้องเป็นผู้น่าเชื่อถือ ถ้ามี |
| คะแนนเปลี่ยนระหว่างวง | ใช้คะแนน ณ ตอนเข้าวง (attestation) ตลอดวง — คาดเดาได้และตรวจสอบได้ |

## D3. เพดานดอกเบี้ย/ส่วนลด → **15% ต่อปี (คิดแบบ annualized) ปรับได้โดย admin**

ยังไม่ชัดว่าศาลถือดอกแชร์เป็นดอกเบี้ยตาม ป.พ.พ. ม.654 หรือไม่ จึงเลือก **ค่าที่ปลอดภัยทางกฎหมายไว้ก่อน**
`maxBid = principal × maxAnnualRateBps × period ÷ (365 วัน × 10,000)` และใช้เพดานเดียวกันกับ `fixRateBps` ของวง Fix (ต่องวด)

| กรณี | ผล |
| --- | --- |
| งวดรายเดือน เงินต้น 1,000 บาท | เสนอดอกได้สูงสุด 12.32 บาท/งวด |
| งวดสั้นหรือเงินต้นน้อยจนเพดาน < 1 สตางค์ | สร้างวงประมูลไม่ได้ (แจ้งให้ใช้วง Fix หรืองวดยาวขึ้น) |
| ตัวอย่างใน Figma (±10%/เดือน) | เกินเพดาน — ถ้านักกฎหมายยืนยันว่าดอกแชร์ไม่อยู่ใต้ ม.654 ให้ admin เพิ่ม `maxAnnualRateBps` ได้ทันทีโดยไม่ต้อง deploy ใหม่ (มีผลกับวงที่สร้างหลังจากนั้น) |
| เพดานเดิม (ไม่เกินเงินต้น) | ยังคงอยู่เป็นเพดานสูงสุดอีกชั้น |

## D4. วงที่ถูกทิ้ง → **วงที่ไม่เริ่มภายใน 30 วันยกเลิกได้โดยใครก็ได้**

| สถานะ | กติกา |
| --- | --- |
| Open (ยังไม่เริ่ม) | นายวงยกเลิกได้ตลอด; หลัง `openTtl` (30 วัน) ใครก็ยกเลิกได้ (worker ทำให้) → คืนโควตานายวง ไม่มีเงินเคลื่อนที่เพราะยังไม่เริ่ม |
| Active แต่สมาชิกหายหมด | วงเดินต่อเองจนจบ: ไม่แจ้งโอน → ผิดนัด, แจ้งโอนแล้วผู้รับเงียบ → ถือว่ารับแล้ว; โควตานายวงคืนเมื่อจบวง |
| ต้องการเลิกวงกลางคัน / ขายมือ / สมาชิกเสียชีวิต | **ไม่รองรับบน chain ในเวอร์ชันนี้** (ต้องตกลงชำระส่วนต่างนอกระบบและมีประเด็นกฎหมาย) — ใช้ dispute + รายงานหลักฐาน; เป็นฟีเจอร์อนาคต |

## D5. ผู้ผิดนัด → **ระงับการใช้งานทั้งแพลตฟอร์มจนกว่าจะชำระ**

- signer ไม่ออก attestation ให้ผู้ที่มีหนี้ผิดนัดค้าง (สร้างหรือเข้าวงใหม่ไม่ได้) จนกว่าจะชำระย้อนหลังครบ
- คะแนน: ผิดนัด −40; ชำระย้อนหลัง (cure) คืน +30 (สุทธิ −10) เพื่อจูงใจให้ชำระ
- ในวงเดิม: ยังคงสถานะผิดนัด (ประมูลไม่ได้ ถูกเลื่อนไปรับท้าย) แม้ชำระแล้ว — คาดเดาได้และกันการเล่นเกม

## D6. ระบบหยุดชั่วคราว (pause) หรือเครือข่ายล่ม → **ไม่มีใครผิดนัดเพราะระบบหยุด**

หลัง admin `unpause` ทุกเส้นตายของการแจ้งโอน/ผิดนัด/ปฏิเสธ จะขยายออกไปอย่างน้อย `grace` (และ 2×grace สำหรับการปฏิเสธ)
นับจากเวลาที่เปิดระบบกลับมา — ถ้าเครือข่ายล่มนาน ให้ admin pause ไว้จนกลับมาปกติ
